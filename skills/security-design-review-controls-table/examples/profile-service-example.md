## What this example demonstrates

- **Row granularity**: one row per endpoint pair, not per control category — an edge with both an authentication and an authorization control gets both in the same row.
- **"Not mentioned" vs. "Not specified by the RFC"**: the Sensitive data column uses "Not mentioned" specifically; every other empty-seeming cell uses "Not specified by the RFC" (or, where the RFC states a requirement without naming the mechanism, that phrasing plus the RFC's exact quoted wording).
- **In/Out split**: the sanitization column always shows both directions on separate lines, even when one side is N/A, so an edge's asymmetry is visible at a glance rather than collapsed into a single sentence.
- **No invented specificity**: four of seven edges show "Not specified by the RFC" for authentication method — the source RFC requires authentication on those edges but never names which mechanism satisfies it, and the table says so rather than filling in a plausible guess.
